Kora

A full-stack programming language that compiles to TypeScript/JavaScript

Build UI and Backend together with architectural discipline by default. One language, three concerns, zero glue code.

Get Started GitHub npm

Why Kora?

🏗️

Architectural Boundaries

Enforced module boundaries. Illegal imports are compiler errors, not conventions.

🔒

Type Safety

Shared types across UI and Backend. Compile-time guarantees, no runtime surprises.

⚡

Zero Glue Code

No fetch boilerplate, no DTO duplication, no Swagger drift. The compiler handles it.

🚀

Standard Output

Compiles to standard TypeScript/JavaScript. Works with React, Next.js, Node.js.

📦

Convention Over Configuration

Sensible defaults. Less configuration, more building.

🔄

Eject Anytime

Output is standard code. Debug, modify, or eject to pure TypeScript anytime.

How to Use Kora

Step 1: Define Your Domain

Start by defining your data models in a domain module:

module domain Post {
  type Post {
    id: UUID
    title: String
    content: String
    author: Author
    createdAt: Date
  }

  type Author {
    id: UUID
    name: String
    email: Email
  }
}

✅ The compiler generates TypeScript interfaces automatically.

Step 2: Create API Endpoints

Define your API with input/output types:

api getPost {
  input {
    id: UUID
  }

  output Post

  handler {
    return PostRepo.find(id)
  }
}

✅ The compiler generates API routes and handler functions.

Step 3: Build UI Pages

Create pages that automatically connect to your APIs:

page PostDetail {
  load(id: UUID) -> Post

  view(post: Post) {
    

      
{post.title}

      
{post.content}

      
By {post.author.name}

    

  }
}

✅ The compiler generates React components and connects them to APIs automatically.

Step 4: Compile and Use

# Check your code
kora check src/domain/post.kora

# Compile to TypeScript
kora build

# Start development
kora dev

✅ Import the generated code in your Next.js/React app from the dist/ directory.

Traditional vs Kora

Traditional Stack

  • ❌ TypeScript interfaces (duplicated)
  • ❌ API route handlers (manual)
  • ❌ Fetch calls in components
  • ❌ Type definitions everywhere
  • ❌ Validation logic scattered
  • ❌ ~40 lines per feature

Kora

  • ✅ Types defined once
  • ✅ APIs auto-generated
  • ✅ No fetch boilerplate
  • ✅ Types shared automatically
  • ✅ Validation built-in
  • ✅ ~10 lines per feature
